Project Overview & Objectives
🎯
What is EventHub?
EventHub is a full-stack event management and booking application. Customers can discover events, search and filter events, view event details, register/book tickets, and manage their bookings. Administrators can create and manage events, categories, venues, and bookings.

The project is intended for fresher developers to demonstrate practical end-to-end development using React.js, Spring Boot, Java 21, PostgreSQL, JPA/Hibernate, Lombok, REST APIs, validation, error handling, Git, and GitHub.

🎯
Project Objectives
  • Build a complete frontend using React.js and Vite.
  • Develop a monolithic backend using Spring Boot and Java 21.
  • Design and implement a relational PostgreSQL database.
  • Create REST APIs and integrate them with the React frontend.
  • Implement authentication and role-based access at a fresher-appropriate level.
  • Practice JPA entity relationships and database CRUD operations.
  • Implement form validation, loading states, empty states, and API error handling.
  • Use reusable React components and a clean backend layered architecture.
  • Use Git/GitHub with meaningful commits and a clear README.

Backend Requirements & Package Structure
  • Create a Spring Boot monolithic application using Java 21.
  • Use Maven for dependency management and build.
  • Use Lombok to reduce boilerplate code where appropriate.
  • Use Spring Data JPA / Hibernate for persistence.
  • Follow a layered architecture: Controller → Service → Repository → Database.
  • Use DTOs for API request/response models instead of exposing entities unnecessarily.
  • Use Bean Validation for request validation.
  • Implement centralized exception handling using an appropriate @ControllerAdvice approach.
  • Return consistent HTTP status codes and JSON responses.
  • Keep business logic inside service classes rather than controllers.
  • Use configuration properties / environment variables for database and application settings.
📁 Suggested Backend Package Structure
com.example.eventhub
├── controller // REST controllers — handle HTTP requests/responses
├── service // Business logic layer
├── repository // Spring Data JPA repositories
├── entity // JPA entity classes mapped to DB tables
├── dto // Data Transfer Objects (request & response models)
├── exception // Custom exceptions + @ControllerAdvice handler
├── config // Security, CORS, app configuration
├── mapper (optional) // Entity ↔ DTO mapping utilities
└── EventHubApplication.java

Database Design & Relationships
🗄️
Database
Use PostgreSQL as the primary relational database. The trainee must identify appropriate primary keys, foreign keys, uniqueness constraints, nullable/non-nullable fields, and relationships before implementation.
EntityImportant Fields / Purpose
Userid, name, email, password, phone, role, createdAt
Roleid, name; may also be represented as an enum depending on design
EventCategoryid, name, description, status
Venueid, name, address, city, capacity
Eventid, title, description, category, venue, date/time, price, totalSeats, availableSeats, status
Bookingid, user, bookingDate, totalAmount, ticketCount, status
BookingItem / Ticketid, booking, event, quantity, unitPrice, subtotal
Attendeeid, booking, name, email, phone; if attendee-level data is required
🔗 Expected Database Relationships
  • One User can have many Bookings.
  • One EventCategory can have many Events.
  • One Venue can host many Events.
  • One Booking can contain one or more booking items / ticket records.
  • One Event can be referenced by many booking items / ticket records.
  • A Booking can have attendee information depending on the selected design.

Search, Filtering & Booking Requirements
🔍 Event Search & Filtering
  • Search by event title or relevant text fields
  • Filter by category
  • Filter by city / location
  • Filter by event date / date range
  • Filter by price range where practical
  • Support sorting (date or price) where practical
  • Handle no-result scenarios clearly
🎟️ Booking Flow
  • Customer selects an event
  • Customer selects number of tickets
  • System validates ticket quantity & available seats
  • Customer enters attendee / contact details
  • System calculates booking amount
  • Booking stored in PostgreSQL
  • Available seats updated appropriately
  • Customer receives booking confirmation screen
  • Customer can view booking under My Bookings
✅
Payment Gateway
Real payment gateway integration is NOT required for this fresher project. A simulated booking/payment confirmation flow is sufficient.
9
Validation, Error Handling & Security
✔️ Validation
  • Required fields validated on frontend
  • Backend validation also required
  • Email format validation
  • Ticket quantity must be positive & within capacity
  • Event date validated by business rule
  • Price/seat counts must not be negative
  • Duplicate/invalid records return meaningful errors
⚠️ Error Handling
  • User-friendly messages for API failures
  • Proper 4xx responses for client errors
  • 404 for missing resources
  • Centralized exception handling
  • No stack traces to frontend
  • Loading and retry/empty states shown
🔐 Security
  • Passwords never stored as plain text
  • Spring Security for authentication
  • Admin endpoints protected
  • Customer endpoints protected
  • No hard-coded credentials or secrets
  • Use env / config variables for secrets
  • Do not commit .env files to GitHub

Final Submission & Project Rules
📦 Final Submission Checklist
  • GitHub repository containing frontend and backend source code
  • Working React.js + Vite frontend
  • Working Spring Boot monolithic backend using Java 21
  • PostgreSQL database implementation
  • Integrated end-to-end application
  • README.md with complete setup and run instructions
  • API documentation or API collection/document
  • Database schema / ER diagram
  • Project screenshots
  • Word / PDF project documentation
  • Google Drive / documentation link if required by trainer
📏 Project Rules
  • Do not use microservices — backend must be monolithic
  • Use Java 21 for the backend
  • Use PostgreSQL as the database
  • Use Lombok appropriately; do not use it to hide understanding
  • Do not hard-code database credentials or secrets
  • Do not use real payment processing
  • Do not add features outside the requirements without approval
  • All major functionality must work end-to-end before optional enhancements
🎓
Fresher-Level Expectations
The trainee should be able to explain every major part of the implementation — React components, hooks, routing, state management, Controller/Service/Repository responsibilities, JPA entity relationships, REST methods and HTTP status codes. The trainee should be able to debug frontend, API and database issues independently. The trainee should not copy a complete project without understanding the implementation.
